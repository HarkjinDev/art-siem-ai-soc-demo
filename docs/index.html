01 / PROJECT OVERVIEW

문제 정의와 구축 목표

보안 이벤트의 탐지, 분석, 정책 개선 제안을 분리된 도구가 아닌 하나의 워크플로로 구성했습니다.

PROBLEM

경보 대응의 반복 업무

SIEM 이벤트를 사람이 수동으로 확인·요약하고 심층 분석과 정책 제안을 작성하는 과정의 연결 비용을 줄이는 데 초점을 맞췄습니다.

APPROACH

단계형 AI SOC

Wazuh 수집·중복 제거·선별(L0), AI 초기 분석(L1), 심층 분석(L2), Sigma 검토(L3)를 독립된 단계로 구성했습니다.

SAFETY

검토와 배포의 분리

AI가 생성한 Sigma는 pySigma 구조 검사를 거쳐 검토 대상으로만 승인됩니다. 실제 Wazuh 룰 자동 적용은 수행하지 않습니다.

sigma-rule.yml · 실제 실행 결과 기반 예시
title: Suspicious Process Discovery via Tasklist
id: f4a5b6c7-d8e9-4f01-a2b3-c4d5e6f7a8b9
status: experimental
description: Detects tasklist via cmd.exe
logsource:
  category: process_creation
  product: windows
detection:
  selection:
    Image|endswith: '\cmd.exe'
    CommandLine|contains: 'tasklist'
  condition: selection
falsepositives:
  - Legitimate administration or monitoring
level: low
tags:
  - attack.t1059.003
  - attack.t1057
실제 생성 Sigma의 핵심 필드·ID를 반영한 공개용 축약 예시입니다. 검사 결과는 구조 및 제한된 필드 샘플 비교이며 Wazuh Manager 실탐지 검증은 아닙니다.
✓ APPROVED_FOR_REVIEW — 사람의 Sigma 검토 대상 승인 이력 기록 완료. 운영 Wazuh에 룰을 배포하지 않았습니다.
공개된 Slack 사례는 실제 테스트 과정에서 받은 메시지를 기반으로 내용을 정리한 재현 화면입니다. 비식별화 및 가독성을 위한 축약이 적용됐으며, 라이브 Slack API 또는 워크스페이스 데이터는 불러오지 않습니다.
